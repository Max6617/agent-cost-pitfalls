**The objective is a paper strong enough to publish in a peer-reviewed journal.** This was NOT written

### What that standard demands — the standing review checklist

From `notes/plans/JOURNAL-PLAN.md` §1, because it is still the best statement of the bar. A journal submission
changes three things: **the evidence has to survive hostile review**, **the effect has to
generalise**, and **the statistics have to be pre-specified**.

| attack | why it lands | what we must have | where we are |
|---|---|---|---|
| **"n=1 task"** | the result could be one task's quirk | 30–40 tasks, stratified by multi-stepness | **31 tasks** — at the floor; one task suite is already the recorded first referee objection |
| **"one model, one provider"** | the cache effect may be one provider's artefact | ≥3 models, ideally 2 providers | **4 models, 4 providers** — met |
| **"you configured your own arm"** | we authored the DSH conditions and work in DSH daily | held-out tasks, pre-registration, no post-hoc tuning, unmodified harnesses, full artifact | pre-registration **filed**; artifact package **not built** |
| **"the cache contaminates the design"** | repeated prefixes warm the cache across runs | measured, randomised, `cost_cold` as the cache-insensitive contrast | measured; both cost variants reported |
| **"p-hacking"** | 10 arms is 45 pairwise tests | pre-registered primary contrast + Holm correction | primary contrast declared; **Holm is WRONG — §5 Step 1** |
| **"cache hit rate is not a contribution"** | it is a measurement, not a theory | pair it with a **mechanism test** | not yet run |
| **"not reproducible"** | alpha software, moving targets | pinned versions, seeds, raw logs, one-command rerun | versions stamped on every record; `collect.mjs` is one command; artifact package not assembled |

**The third row decides the paper — and get the FACT right, because this repo had it wrong in
writing for weeks.** The authors **did not develop DSH and are unaffiliated with it**
(`PRE-REGISTRATION.md:270`, `METHODS.md:275`). DSH is DeepSeek's official open-source harness
(`@deepseek-ai/dsh@0.1.7-rc.2`, MIT); every commit in this repo touches only the disclosed
config/plugin layer. What the authors *did* do is **author the DSH conditions** and work in DSH daily.

So the risk is **not** fabrication in DSH's favour. It is **configuration asymmetry**: the DSH arms
may be configured with more care, or more knowledge of the system, than the third-party arms.
`METHODS.md:282`: *"This is a real asymmetry and it is not eliminated."* That makes the four
mitigations — a hold-out task suite, a primary contrast specified before its own data, **every
harness driven unmodified**, and the artifact release — **the answer to the first question a reviewer
asks**, not optional extras.

### What the journal tier still requires

1. **A second task suite.** The recorded first referee objection is "one task suite". 31 tasks at the

2. **Correct statistics.** A reported result that fails Holm under the filed family is a retraction

3. **The artifact package.** Pinned versions, seeds, raw logs, one-command rerun. The direct answer to

4. **The mechanism test** (`notes/plans/JOURNAL-PLAN.md` §4) — what turns a measurement into a contribution.
5. **Related-work depth and ablations**, both journal-tier and still "to do".

### How this changes the next session's judgement

- **A number that cannot survive a hostile reviewer is a liability, not a deliverable.** Prefer "we do
  not know yet" to a figure that will be retracted.
- **Retractions stay visible.** `notes/records/FINDINGS.md` says it in its own header: *"a paper's credibility rests
  on the retractions being visible too."* Never quietly fix a stale number — move it and record that
  it moved.
- **Pre-declare analysis rules.** At journal tier a rule chosen after seeing the effect is fatal.

## 3. WHAT THIS SESSION FIXED — eight defects, all real, all with reproductions

The pipeline **refused to start four times** before it would spend anything, and every refusal was a
genuine defect. Details matter because several are the class of bug the study keeps retracting over.

### 3.1 The backup TEST was overwriting the live backup root  (`94c89ec`)

`backup-results.mjs` resolved targets as `[--to, ...defaults]` — `--to` was ADDITIVE. So every run of
`backup-results.test.mjs`, the suite whose entire job is to protect the archive, ALSO mirrored its
3-file temp fixture into the real root at `../betterharness-backups`:

- `mirror/ds-full/runs.jsonl`: **3,194,918 bytes of real DeepSeek records → 26 bytes of `{"task":"a"}`**
- `mirror/runs.jsonl` → 13 bytes
- `manifest.json` rewritten to name a `%TEMP%\dsh-exp-backup-test-*\results` as its source
- **nine snapshots named `mmu123 620 runs`**, each 54 bytes of fixture, looking exactly like a
  point-in-time copy of a 620-run matrix

Every existing test still passed, because not one asserted that a run naming its own target leaves
the real one alone.

**Fixed:** `--to` is exclusive (`--also-defaults` opts back in); a mirror refuses a second source
without `--allow-source-change`. Two new tests, watched failing first. **Repaired:** the nine fixture
snapshots are renamed `INVALID-test-fixture__*` with a `NOT-EVIDENCE.json` inside (never deleted —
the tool is append-only) and the rename is recorded in `log.jsonl`; the mirror was re-run from the
real source. **No run record was lost** — `ds-full/runs.jsonl` was git-tracked at `1132da0` and the
14:10 snapshot held it.

### 3.2 The key merge was broken  (`cc894f7`)

The GLM matrix stopped at stage 2: `no usable key for zai in .keys.json / FILL-IN-KEYS.json` — one
stage AFTER `check-providers.mjs` reached z.ai and called it FUNDED. Two stores disagreed because
two modules implemented the merge:

- `.keys.json` — the real keys (zai, anthropic, anthropic_workspace, qwen, openai)
- `FILL-IN-KEYS.json` — a **TEMPLATE**, newer, every slot `PASTE_..._HERE`

`tools/keys.mjs` sorted by mtime and treated `PASTE_` as absent. `collect.mjs` had its own copy doing
`{ ...keys.json, ...FILL-IN-KEYS.json }`, so the template sat ON TOP: zai/openai/qwen/anthropic all
resolved to `null`, and only deepseek worked via the `~/.dsh/.credentials.yaml` fallback.

**Fixed:** `resolveUpstreamKey` moved into `tools/keys.mjs` (`repo` and `dshHome` injectable), and
`collect.mjs` imports it. Five tests. One rule, one implementation.

### 3.3 zai was missing `--max-tokens-ceiling 32768`  (`b18ccbe`, `1012cf6`)

The GLM matrix stopped at preflight with `dsh: 6 runs, 24 requests, 0 2xx, 24 failed` while the other
four harnesses passed against the same gateway. DSH sends `max_tokens=256000`; z.ai's Messages
endpoint accepts `[1,131072]`.

**The evidence is not inference.** `data/milestone-4/gateway.jsonl` is a surviving, complete,
batch-1-shaped GLM matrix (310 runs, 100% solved) and records every deviation the gateway applied:
2,544 × 200 with `max_tokens 256000→32768`, and 248 × 400 with `max_tokens 64` — DSH's auxiliary
request, which **failed in the good matrix too** and never cost a run.

Counting every surviving gateway record by model and harness gave the whole treatment table:

| model + dsh | requests | outcome |
|---|---|---|
| glm-5.3-flash | 3,166 | 2,875 ok, **all capped**, 0 ok uncapped |
| qwen3.8-flash | 31 | 31 ok, **all capped**, 0 ok uncapped |
| gpt-6-luna | 26 | 26 ok, **none capped**, 26 ok uncapped |
| deepseek-flash | 4,896 | 4,896 ok, none capped (256000 accepted) |

So the ceiling is required for GLM and Qwen, and **luna must NOT have one** — adding it would be an
unmeasured change. The flag table moved to `tools/collect-gateway.mjs` so it is testable, with
7 tests pinning the ceiling, the forced model, forced effort, and the per-provider cache-breakpoint
treatment (Qwen ON; DeepSeek and GLM OFF).

### 3.4 `verify` checked zero-DURATION, not zero-COST  (`da11ae2`)

The check was `!error && durationMs === 0` under a comment about zero cost. **Run records carry no
cost field and no token counts at all**, so duration was the only proxy — and the wrong one: a run

precisely the failure the check exists for: a harness that reaches nothing while its zeros read as
results. Now cross-references gateway usage by runId, scanning EVERY gateway log in the run root
(a resumed matrix gets a new id and a new log). Validated as 0-false-positive against the signed-off
620-run DeepSeek matrix.

## 7. WHERE TO BE CAREFUL — gotchas that cost real time

### 7.1 PowerShell will silently eat your `$` and your backticks

A `git commit -m "… $4.8685 …"` had `$4` interpolated to nothing, the command failed, and **the
failure was invisible** because I had printed only stdout. A separate `node -e "…"` diagnostic was
mangled by PowerShell quoting into a parse error.

**Do this instead:** write the message with the `write` tool to a temp file and use
`git commit -F <file>`. Never put `$`, backticks, or nested quotes in a PowerShell command line.
Also: a backtick inside a JS template literal TERMINATES the template — this broke a `run_code`
program that embedded PowerShell ``` `n ``` escapes.

### 7.2 Killing processes

**Do NOT kill a process from a plain pwsh tool call** — it can tear down the tool's own Windows Job
runner. Use `run_in_background: true` for kills, or `Invoke-CimMethod -MethodName Terminate`.
**Better: do not kill matrices at all.** The spend meter and the watchdogs stop them gracefully and
`--resume` continues from disk. Letting the meter bite cost ~10 minutes; killing by hand risks the
session.

### 7.3 Long waits

`run_code` has a **120 s default deadline and a 600 s cap**. Background collection jobs run for
hours: start them with `run_in_background: true` and collect with `job_output` (`wait: true`,
`timeout_ms` up to the program budget). Approximately one 9.5-minute wait per turn is the practical
maximum; a 5-hour matrix is ~30 turns.

### 7.4 Matrices are long and slow, and the rate is task-driven, not a fault

The suite runs cheapest-first: `example-fix` averages 47 s/run, `fetch-heavy-*` 137–343 s. Early ETA
readouts are meaningless. Measured wall-clock: GLM 299 min, luna 206 min, qwen 350 min + 69 min
resume. **Before concluding a matrix has stalled, check per-task durations against `ds-full`.**

### 7.5 The backup is APPEND-ONLY and snapshots accumulate

It never deletes and never prunes. Unchanged files are matched on size AND mtime. A live matrix
will show `DRIFT` against the mirror between incremental backups — that is normal, not corruption.
`--verify` exiting 0 is the thing to check, and it is what `collect.mjs` signs off against.

### 7.6 Keys

`.keys.json` holds the real keys. `FILL-IN-KEYS.json` is a TEMPLATE full of `PASTE_..._HERE`.
Resolve keys ONLY through `tools/keys.mjs` (`loadKeys`, `resolveUpstreamKey`). Keys go in the
child's **ENVIRONMENT, never argv** — argv appears in process listings and job labels.

### 7.7 The credit window no longer invents outages

It goes red only on an explicit `state: 'empty'`. `collect.mjs` sends `'empty'` only for a genuine
`check-providers` credit failure and `'warn'` for the spend meter. **If you see red, still verify
before acting**: the correct first move is to check for credit-classified runs, not to top up.
Alerts are sticky until `POST /clear`.

### 7.8 The scratch browser profile

`results/_scratch/credit-alert-profile` is held by `msedgewebview2`. It is harmless (untracked, and
the backup skips `_scratch`). **Do not kill `msedgewebview2` — it is a Windows component.**

## 8. HOW TO VERIFY A MATRIX — the recipe that caught everything above

Never accept `collect.mjs`'s own summary. Run these independently:

1. **Cells.** `distinct(task|arm|seed)` must equal `tasks × arms × seeds`, with no missing cells and
   duplicates explained. (`records` may exceed `cells` by design — see §2.)
2. **Outcomes.** Count `error` records, `timedOut`, and non-zero exits. **Investigate any run whose
   failure contradicts its own output** (this is how §4.2 was found: 21/21 passing but `solved=false`).
3. **Spend.** Re-derive per runId with `costOf(model, usage)` over EVERY `*gateway*.jsonl` in
   `results/`. Reconcile: `whole gateway log = matrix runs + preflight + pilot`. Expect a few cents
   of meter-tick lag; a large gap in either direction is the finding.
4. **Zero-cost unexplained:** `!error && no billable usage` must be 0. This is the "zeros that read
   as results" guard.
5. **Fields:** `harnessVersion` and `fixture` present on 100% of records;
   `fixture.gradedOnEditedTests` counted.
6. **Backup:** `node tools/backup-results.mjs --verify` must exit 0.
7. **Git:** working tree clean, and the data files committed.

A reusable script for (1), (2), (3), (4) and (5) was used repeatedly this session; rebuild it from
the description above rather than trusting a path in `%TEMP%`.
